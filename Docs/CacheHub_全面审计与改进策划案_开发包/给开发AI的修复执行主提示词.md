1. `CacheHub_仓库全面审计与改进策划案_V1.0.md`

3. 原项目中的 `Docs/ai/AI_DEV_STATE.json`、总策划和执行手册。

## 强制执行规则

- 不删除长期功能；尚未实现的能力标记为 scaffold/planned 并移到独立模块。
- 严格按 R0 → R1 → R2 → R3 → R4 顺序推进。P0 未清零前禁止开发 Semantic、LSP、企业或新 UI 功能。
- 每次只处理一个任务 ID；先复现或写失败测试，再修改代码。
- 不以“文件存在、接口存在、测试数量多”作为完成证据。
- 每个任务完成必须提供：修改文件、关键设计、测试命令、测试结果、剩余风险、回滚方式。
- 安全修复必须包含攻击夹具；数据修复必须包含迁移和旧数据兼容测试。
- 不修改 Git 历史，不自动推送；每个独立任务通过测试后提交一次。
- 文档中的能力状态必须与实际 capability 契约测试一致。
