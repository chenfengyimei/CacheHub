# ADR-0005: Gateway 从 Core 拆分为独立项目

## 状态

Accepted

## 日期

2026-08-07

## 背景

CacheHub 的 Gateway 模块（HTTP 代理服务器、Provider 路由、SSE 流式转发）最初实现在 `CacheHub.Core` 项目内，作为 `Core/Gateway/` 和 `Core/Providers/` 目录。

审计（ARCH-P2-001）指出这违背了"可选模块独立关闭"原则：

- Core 承载了运行时模块（Gateway/Provider），职责与变化半径过大
- CLI 和 Desktop 间接拉入了 Gateway 代码，即使用户不需要网关功能
- 测试和依赖管理不够清晰

## 决策

将 Gateway 和 Provider 实现代码从 `CacheHub.Core` 拆分到独立的 `CacheHub.Gateway` 项目。

### 具体变更

- 新建 `src/CacheHub.Gateway/` 项目（csproj 引用 Core，不依赖 Storage/Context/Indexing）
- 移动文件：
  - `GatewayModels.cs` → `CacheHub.Gateway/`
  - `Server/GatewayServer.cs` → `CacheHub.Gateway/Server/`
  - `Streaming/SseStreamParser.cs` → `CacheHub.Gateway/Streaming/`
  - `ProviderModels.cs` → `CacheHub.Gateway/`
  - `ProviderRouter.cs` → `CacheHub.Gateway/`
- 命名空间更新：
  - `CacheHub.Core.Gateway` → `CacheHub.Gateway`
  - `CacheHub.Core.Gateway.Server` → `CacheHub.Gateway.Server`
  - `CacheHub.Core.Gateway.Streaming` → `CacheHub.Gateway.Streaming`
  - `CacheHub.Core.Providers` → `CacheHub.Gateway.Providers`
- CLI 和 Tests 项目新增对 `CacheHub.Gateway` 的引用
- `.editorconfig` 新增 CacheHub.Gateway 分析器抑制规则
- Core 保留 Semantic 和 LSP 的契约/模型（仍为 scaffold），但不包含 Gateway 运行时

### 依赖链（重构后）

```
CacheHub.Core          ← 纯领域模型、契约、标识符
  ↑
CacheHub.Storage       ← SQLite、迁移、仓储、FTS5
CacheHub.Indexing      ← 扫描、忽略规则、解析器（只依赖 Core）
CacheHub.Gateway       ← Gateway Server、Provider、SSE（只依赖 Core）
  ↑
CacheHub.Context       ← 召回、排序、选择、引擎（依赖 Core+Storage+Indexing）
  ↑
CacheHub.Cli           ← CLI 入口（依赖全部）
CacheHub.Desktop       ← Web UI（依赖全部）
```

## 理由

1. **职责分离**：Core 只包含领域模型和契约，Gateway 是可选运行时模块
2. **变化隔离**：Gateway 的 HTTP/Provider 实现变更不影响 Core/Context/Indexing
3. **按需引用**：不需要 Gateway 的场景可以不引用该项目
4. **测试清晰**：Gateway 测试独立于 Core 领域测试

## 影响

- CLI 和 Desktop 仍引用 Gateway（因为 CLI 有 `gateway start` 命令）
- 未来如果 Gateway 改为独立进程，只需修改 CLI/Desktop 的引用方式
- Semantic 和 LSP 的模型仍在 Core 中，作为契约定义；实现需后续独立项目

## 验证

- `dotnet build` 通过（0 错误 0 警告）
- `dotnet test` 通过（772 测试）
- `dotnet format --verify-no-changes` 通过
- 所有 Gateway/Provider 测试在新命名空间下正常工作
